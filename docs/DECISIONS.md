# DECISIONS

Format: `## D-001 Naslov (datum)` → Kontekst → Odluka → Posljedice.

## D-001 Backend u Go-u, Postgres umjesto SQLite-a (2026-11-06)
**Kontekst:** Najveći prigovori na Jellyfin su performanse velikih (posebno glazbenih) biblioteka i zaključavanje SQLite baze.
**Odluka:** Go server + PostgreSQL 17 (pgvector, pg_trgm) + River job queue + Valkey.
**Posljedice:** Jedan dodatni kontejner (Postgres), ali skalabilnost, pravi indeksi, AI pretraga i bez DB lockova.

## D-002 OpenAPI kao izvor istine (2026-11-06)
**Odluka:** `api/openapi.yaml` generira Go server sučelja (ogen), TS klijent i Swift klijent.
**Posljedice:** Web i iOS nikad ne zaostaju za serverom; svaka promjena API-ja ide kroz spec.

## D-003 iOS: AVPlayer primarno, MPVKit fallback; bez APNs-a (2026-11-06)
**Kontekst:** App se sideloada kroz Feather; neki entitlementi ne prežive resign.
**Odluka:** AVPlayer + HLS za najbolji HDR/DV/PiP/AirPlay; MPVKit za direct play egzotičnih formata; notifikacije preko WebSocketa/ntfy umjesto APNs-a; discovery preko Bonjoura.

## D-004 Projektni identitet i infrastruktura (2026-11-06)
**Kontekst:** Otvorena pitanja iz PLAN.md §10.
**Odluka:** Repo `streamero-app/streamero` (GHCR `ghcr.io/streamero-app/streamero`); bundle ID `net.scyde.streamero`; reverse proxy Caddy (zamijenjeno nginxom, vidi D-010); GPU na serveru još nepoznat → prvi HW put koji testiramo je VA-API. Pristup je clean-room (ne fork Jellyfina). Dev instanca: demo.streamero.net, produkcija streamero.net.
**Posljedice:** `GH_OWNER` default u compose je `streamero-app`. Ako se GPU pokaže NVIDIA, NVENC put ide prvi u P5.

## D-005 Go 1.26 umjesto 1.25 (2026-11-06)
**Kontekst:** PLAN.md predviđa Go 1.25+. Aktualne verzije River, goose i go-redis zahtijevaju Go ≥ 1.26.
**Odluka:** `go 1.26.4` u `server/go.mod`, builder image `golang:1.26-trixie`.
**Posljedice:** Nema — plan je govorio „1.25+".

## D-006 TypeScript 5.9 i supply-chain politika za npm (2026-11-06)
**Kontekst:** TypeScript 7 (nativni kompajler) mijenja JS API, pa `openapi-typescript` puca. pnpm 12 (koji corepack povuče bez pina) odbija pakete mlađe od 24 h.
**Odluka:** TypeScript `~5.9` dok alati ne podrže 7. `packageManager: pnpm@10.28.0` u `web/package.json`; `web/.npmrc` s `minimum-release-age=2880` (2 dana) — svjesna zaštita od kompromitiranih svježih paketa.
**Posljedice:** Nove verzije paketa ulaze s ~2 dana zakašnjenja. Upgrade na TS 7 kad openapi-typescript doda podršku.

## D-007 Web build ide direktno u Go embed direktorij (2026-11-06)
**Odluka:** `vite build` piše u `server/internal/webui/dist` (gitignored, osim `.keep`). Go binarij servira SPA s fallbackom na `index.html`; ako web nije buildan, servira kratku poruku umjesto pada.
**Posljedice:** `go build` radi i bez Node toolchaina (za backend-only razvoj).

## D-008 Worker bez HTTP healthchecka u P0 (2026-11-06)
**Kontekst:** Image `HEALTHCHECK` gađa `/healthz`, a worker nema HTTP listener.
**Odluka:** U compose je healthcheck za `worker` isključen; živost se vidi kroz River job statistike (periodični `system.heartbeat` job svake minute).
**Posljedice:** U P10 (admin dashboard) dodati prikaz zadnjeg heartbeata workera; po potrebi mali health listener u workeru.

## D-009 Bez chi `RealIP` middlewarea (2026-11-06)
**Kontekst:** `middleware.RealIP` vjeruje `X-Forwarded-For`/`X-Real-IP` bez obzira na izvor (IP spoofing; staticcheck SA1019).
**Odluka:** Ne koristimo ga. Pravo rješenje je postavka „known proxies" (FEATURES §1, P10) koja vjeruje forward headerima samo od navedenih proxyja.
**Posljedice:** Do P10 logovi i rate limit vide IP reverse proxyja.

## D-010 nginx umjesto Caddyja za demo.streamero.net (2026-11-06)
**Kontekst:** D-004 je predvidio Caddy. Na serveru već radi sistemski nginx (80/443, certbot) za ostale domene, a port 8787 zauzima drugi servis.
**Odluka:** Reverse proxy je postojeći nginx sa site datotekom `deploy/nginx/demo.streamero.net.conf` (bez bufferinga, 1 h timeout, WebSocket upgrade); TLS kroz `certbot --nginx`. Demo stack sluša samo na `127.0.0.1:8797` (`HTTP_PORT` u `deploy/.env`).
**Posljedice:** Nema drugog procesa na 80/443. Instalacija sitea i certifikat traže root (sudo) na serveru. Za korisnike ostaje bilo koji reverse proxy; nginx primjer je u repou.

## D-011 *arr ekosustav i Seerr/Jellyseerr kao obavezni, ne „extras" (2026-11-06)
**Kontekst:** Korisnik traži da Streamero radi s Prowlarr, Radarr, Sonarr, Lidarr, Bazarr, Seerr/Jellyseerr i ostatkom *arr stacka. Plan ih je imao u P13 (requests, webhooks) i P14 (opcionalni Jellyfin-compat sloj). Ti alati se na media server spajaju na tri načina:
- **Seerr / Jellyseerr / Overseerr-fork** podržavaju samo Plex, Jellyfin i Emby kao media server (login korisnika, uvoz korisnika, sync dostupnosti po TMDB/TVDB ID-u, „Play on" linkovi). Bez Jellyfin-kompatibilnog API-ja ne mogu raditi.
- **Radarr / Sonarr / Lidarr** (i Whisparr, Readarr-forkovi) u *Connect* imaju „Emby / Jellyfin" (poziv da je putanja promijenjena → refresh) i generički *Webhook* (JSON s putanjama).
- **Bazarr** piše `.srt`/`.ass` pokraj datoteke i ne zove media server; **Prowlarr** sinkronizira indeksere samo prema *arr aplikacijama i nema nikakvu vezu s media serverom.
**Odluka:** Nova faza **P4b — *arr ekosustav** (nakon P4, jer treba korisnike iz P1, scanner iz P2, TMDB/TVDB ID-eve iz P3 i stranice detalja iz P4 za „Play on" linkove):
1. **Compat API podskup** (prije P14 „opcionalno") pod prefiksom `/compat` (konfigurabilno), implementiran isključivo po javnoj OpenAPI specifikaciji i javnoj dokumentaciji klijenata; samo endpointi koje Seerr/Jellyseerr stvarno koriste (auth po imenu, javni system info, korisnici, biblioteke/views, items s ProviderIds, sezone/epizode, nedavno dodano, library refresh). Svugdje u odgovorima ProductName ostaje „Streamero" — nigdje „Jellyfin" u UI-ju ni identifikatorima.
2. **Ulazni webhooks za *arr**: generički *Webhook* payload Radarra/Sonarra/Lidarra i compat „Emby/Jellyfin" notifikacija → ciljani scan samo zahvaćene putanje (kroz `library.ResolveSafePath`).
3. **Sidecar podnaslovi (Bazarr)**: fsnotify + periodični lagani scan sidecar datoteka; dodatno API endpoint za Bazarrov post-processing hook.
4. **Prowlarr**: nema integracije s media serverom — ništa se ne implementira osim (opcionalno, P10) prikaza zdravlja *arr servisa na admin dashboardu.
5. Vlastiti Requests (P13) ostaje, ali Seerr/Jellyseerr mora raditi i bez njega.
**Posljedice:** Compat sloj se sad održava kao javni ugovor; testira se e2e protiv **stvarnih kontejnera** Seerr, Jellyseerr, Radarr, Sonarr, Lidarr i Bazarr u CI-ju (compose profil `arr`). Podržani podskup je dokumentiran u `docs/INTEGRATIONS.md`; nepodržani endpointi vraćaju 404, ne lažne podatke. P14 „Jellyfin-compat za Infuse/Swiftfin" se nadograđuje na isti sloj.

## D-012 Sesije: Bearer token za aplikacije, HttpOnly cookie za web; setup kod (2026-11-06)
**Kontekst:** PLAN §5.5 predviđa header `Authorization: Streamero token="…"`. Web klijent ne bi smio držati token u JavaScriptu (XSS), a demo je javno dostupan pa bi prvi posjetitelj mogao „preuzeti" server kroz setup wizard.
**Odluka:**
- Standardni `Authorization: Bearer <token>` (OpenAPI `http/bearer`, ogen ga generira) za iOS i integracije; web dobiva isti token kao `streamero_session` cookie (`HttpOnly`, `SameSite=Strict`, `Secure` kad je veza HTTPS, i iza proxyja preko `X-Forwarded-Proto`). Server cookie interno pretvara u Bearer.
- Token: 32 B random, u bazi samo SHA-256; sesija vrijedi 30 dana i produžuje se korištenjem.
- Prvi admin se može napraviti samo uz jednokratni **setup kod** koji server ispisuje u log pri startu (`setup_code=XXXX-XXXX`) ili je zadan s `STREAMERO_SETUP_CODE`; 10 pogrešnih kodova → 1 min pauze.
- Lozinke min. 8 znakova (argon2id); lockout 5 pogrešnih → 15 min, atomično u SQL-u; nepostojeći korisnik odgovara isto kao kriva lozinka.
- Rate limit po IP-u odgođen do postavke „known proxies" (D-009) — iza nginxa bi svi klijenti imali isti IP.
**Posljedice:** API ključevi (P1, sljedeći korak) koriste isti Bearer header. CSRF: mutacije su JSON (cross-site forma ih ne može poslati bez CORS preflighta), a cookie je `SameSite=Strict`.

## D-013 Dozvole kao jsonb s defaultima u kodu; limit uređaja odjavljuje najstariji (2026-11-06)
**Kontekst:** P1 traži model dozvola prije nego što postoje biblioteke, reprodukcija i Live TV; Jellyfin pri prekoračenju broja sesija odbija novu prijavu.
**Odluka:** `users.permissions jsonb`; nedostajući ključevi dobivaju `auth.DefaultPermissions()` pri čitanju, pa nove dozvole ne trebaju migraciju podataka. Admin uvijek smije sve. Kad korisnik s limitom N uđe na N+1. uređaj, odjavljuje se najdulje neaktivna sesija (umjesto odbijanja), jer bi inače korisnik sa zaboravljenom sesijom ostao zaključan.
**Posljedice:** Svaka buduća značajka mora provjeriti svoju dozvolu (`Principal.User.Permissions`) i imati test za to.

## D-014 Known proxies kao env postavka; rate limit u memoriji (2026-11-06)
**Kontekst:** D-009 je odgodio pravi IP klijenta do „known proxies". Bez toga rate limit iza nginxa vidi samo jedan IP.
**Odluka:** `STREAMERO_TRUSTED_PROXIES` (CIDR/IP lista) — `X-Forwarded-For` se čita samo kad je izravni peer na listi, i to zdesna (prvi netrusted hop), pa klijent ne može podmetnuti IP. Token bucket po IP-u u memoriji procesa (20/min, burst 10) na prijavi, setupu, Quick Connect startu, pozivnicama i PIN-u profila; IP ide u audit log. Postavka je env (ne u admin UI-ju) jer pogrešna vrijednost može zaključati sve ili otvoriti spoofing.
**Posljedice:** Više instanci servera bi trebalo dijeljeni limiter (Valkey) — tek kad bude potrebno. Demo: `172.18.0.1` (gateway compose mreže).

## D-015 Medijski bajtovi izvan OpenAPI-ja, iza HMAC potpisa (2026-11-07)
**Kontekst:** Direct play treba HTTP Range, HLS segmente i playlistu koje generira ffmpeg, a playeri (`<video>`, AVPlayer, Chromecast) ne šalju auth header. OpenAPI generator (ogen) nije prikladan za byte-range streamove.
**Odluka:** `POST /api/v1/items/{id}/playback` (u specifikaciji) odlučuje direct/remux/transcode i vraća kratkotrajne potpisane URL-ove; same bajtove poslužuje `/stream/*` izvan OpenAPI-ja: `/stream/file/{fileId}/…` (Range), `/stream/hls/{session}/…` (fMP4 HLS, playlista se prepisuje s potpisom), `/stream/sub/{fileId}/{n}.vtt` (WebVTT). Potpis = HMAC-SHA256(scope, exp) s ključem generiranim pri prvom pokretanju (u bazi); scope je prefiks `/stream/<vrsta>/<id>/`, vrijedi 8 h. Putanja iz baze prolazi kroz `ResolveSafePath` pri svakom zahtjevu. HLS koristi fMP4 segmente (radi i za HEVC/AV1 copy), ffmpeg sesije se gase nakon 90 s bez zahtjeva.
**Posljedice:** Klijenti nikad ne grade stream URL-ove sami. Napredak gledanja ide po profilu (`user_item_data.owner_id`); kod HLS-a koji počinje od `startMs` klijent zbraja offset.

## D-016 Compat API kao ručno pisani handleri pod `/compat` (2026-11-07)
**Kontekst:** D-011 traži da Seerr/Jellyseerr i *arr „Emby/Jellyfin" veza rade sa Streamerom. Njihov API oblik definira tuđa javna OpenAPI specifikacija, ne naša.
**Odluka:** `server/internal/compat` implementira samo potreban podskup (system info, AuthenticateByName, korisnici, views, items s ProviderIds i MediaSources, sezone/epizode, latest, slike, `/Auth/Keys`, `/Library/Media/Updated`, `/Library/Refresh`, `web/#/details` preusmjerenje) kao chi handlere, iz javne dokumentacije i promatranja ponašanja stvarnih klijenata (Jellyseerr 2.7.3, Radarr 5.26) — bez čitanja njihovog izvornog koda. Ne ulazi u `api/openapi.yaml` (to je naš API). `ProductName` je uvijek „Streamero". Ključ napravljen preko `/Auth/Keys` je čitljiv samo 10 min u memoriji (Streamero inače čuva samo hash). Prijava preko compata ide kroz isti rate limit.
**Posljedice:** Ponašanje je pokriveno integracijskim testom (`TestCompatAPIIntegration`); ručna provjera sa stvarnim Jellyseerrom i Radarrom opisana je u INTEGRATIONS.md. Proširenje za Infuse/Swiftfin (P14) nadograđuje isti paket.

## D-019 Vizualni smjer „Kino platno" (2026-11-09)
**Kontekst:** izvedba „Ambijenta" (D-018) korisniku je izgledala djetinjasto: sve je bilo zaobljena „pilula", film je stajao u malom zaobljenom okviru, a posteri su bili nasumični kadrovi. Ponuđena su tri smjera s pravim posterima i snimkama (A „Kino platno", B „Festivalski program", C „Videoteka"); korisnik je izabrao A.

Naslovi su postavljeni široko i velikim slovima kao u odjavnoj špici (Archivo, os širine; na iOS-u sistemski font `.width(.expanded)`). Boja filma pojavljuje se samo kao akcent: linija napretka, oznaka aktivne navigacije i fokus. Navigacija je tekstualna s podcrtom. ## D-020 Ugrađena proširenja umjesto sustava pluginova (2026-11-09)
**Kontekst:** korisnik traži „pluginove kao Jellyfin, posebno Jellyfin Enhanced, ali ugrađeno u Streamero, da se ne koristi plugin". Pluginovi treće strane unutar servera (učitavanje koda) donose sigurnosne rizike, pucaju na nadogradnjama i teško su izvedivi u Go binariju bez CGO-a; prijenos njihovog koda nije dopušten (clean-room).
**Odluka:** funkcije za koje drugi serveri koriste pluginove pišemo kao ugrađene module s prekidačima (Postavke → Proširenja, `GET/PUT /enhancements`): oznake kvalitete, „Iznenadi me", zaslon pauze, uklanjanje iz „Nastavi gledati", pomoć za prečace, slika u slici, zahtjevi u pretrazi, poveznice na Radarr/Sonarr. Integracije s vanjskim alatima idu preko njihovih javnih API-ja (Seerr, Radarr, Sonarr) i preko postojećih webhooka/obavijesti te compat API-ja.
**Posljedice:** novi „plugin" je nova funkcija u kodu s testovima i prekidačem. Ako se kasnije pokaže potreba za vanjskim proširenjima, prvi korak su webhookovi i ograničeni skriptni hookovi izvan procesa servera, ne učitavanje koda.

## D-021 iOS: obični URLSession klijent za medijski API (2026-11-09)
**Kontekst:** paritet s Androidom traži oko 100 API poziva; generirani swift-openapi klijent za svaki poziv traži po switch nad odgovorima, a lokalno nema Swift alata pa se sve provjerava tek u CI-ju.
**Odluka:** medijski i administracijski pozivi idu kroz ručno pisani `MediaClient` (URLSession + Codable modeli u `Core/API/Models.swift`) po uzoru na Android `api/Api.kt`. Prijava, Quick Connect i provjera servera ostaju na generiranom klijentu. Polja koja spec traži kao obavezna nisu opcionalna u modelima, pa se uvijek šalju (i kad su false/0); nil opcionalna polja se izostavljaju.
**Posljedice:** spec ostaje izvor istine, ali promjene API-ja treba ručno prenijeti u `Models.swift`. Titlovi se crtaju preko videa (WebVTT se dohvaća i parsira) jer AVPlayer ne može učitati vanjske titlove uz obični URL.

## D-022 Vanjski ffmpeg build ostaje, ime samo kao naziv paketa (2026-11-10)
**Kontekst:** slika servera instalira ffmpeg 8 build s ugrađenom podrškom za VA-API, QSV, NVENC, Vulkan i OpenCL, koji se zove `jellyfin-ffmpeg8`. Pravilo iz CLAUDE.md kaže da se to ime ne smije pojaviti u našim identifikatorima.
**Odluka:** paket ostaje jer je jedini gotovi build s tim hardverskim ubrzanjima i ispravnim tonemappingom. Zamjena (npr. statički build plus Debianovi VA driveri) traži provjeru na stvarnom Intel/AMD/NVIDIA hardveru, koji nemamo. Ime ostaje samo tamo gdje mora: naziv paketa, njegov repozitorij i putanja do programa u Dockerfileu te THIRD_PARTY.md. Build opcija se sada zove `FFMPEG_SOURCE=extended`, a stara vrijednost `jellyfin` i dalje radi. Komentari u kodu više ne spominju ime.
**Posljedice:** program se samo pokreće kao vanjski proces, nikad se ne linka. Ako se kasnije nađe jednako dobar build pod neutralnim imenom, mijenja se samo blok u Dockerfileu.

## D-024 Uvoz povijesti gledanja iz Jellyfina (2026-11-10)
**Kontekst:** vlasnik gasi Jellyfin i ne smije izgubiti po korisniku: pogledano, broj i datum gledanja, mjesto zaustavljanja, favorite i popise za reprodukciju. Clean-room pravilo vrijedi: koristi se samo javna REST API dokumentacija / javni OpenAPI opis (`/System/Info`, `/Users`, `/Items` s `filters=IsPlayed|IsResumable|IsFavorite`, `/Playlists/{id}`, `/Playlists/{id}/Items`, zaglavlje `Authorization: MediaBrowser … Token="…"`), bez SDK-ova i izvornog koda.
**Odluka:**
- Admin upisuje adresu i API ključ (Postavke → Uvoz). Ključ se, kao Seerr/Bazarr ključevi, nikad ne vraća kroz naš API; za razliku od njih ne čuva se trajno: stoji u `import_runs.secret` samo dok je uvoz na čekanju ili u tijeku, worker ga briše na kraju (i kod greške), a uvozi stariji od 4 h (dulje od timeouta joba) proglašavaju se prekinutima i ključ se briše. Job ima `MaxAttempts: 1` jer ključa nakon kraja više nema.
- Korisnici se povezuju po korisničkom imenu bez obzira na velika/mala slova; admin može promijeniti ili preskočiti svakog. Podaci idu u glavni profil (`owner_id` = id korisnika). Dva izvorna korisnika na istog Streamero korisnika spajaju se istim pravilima kao ponovni uvoz.
- Uparivanje: TMDb/IMDb/TVDB oznake (po vrsti stavke) → epizode/sezone preko oznake serije + S/E (uključujući multi-episode datoteke) → putanja datoteke uz opcionalno preslikavanje prefiksa (najdulji prefiks, Windows putanje se normaliziraju; Streamero strana mora proći `library.ResolveSafePath`) → naslov + godina (normalizirani naslov, i metadata i naslov iz imena). Isti film u više biblioteka dobiva podatke u svim kopijama. Glazba se uparuje samo po putanji.
- Spajanje: pozicija = ticks / 10 000 (cijele ms); pogledano briše poziciju i daje play count ≥ 1. Pobjeđuje noviji „zadnje gledano"; play count je maksimum, favorit se nikad ne skida. Zato je ponovni uvoz idempotentan i ne pregazi noviji napredak iz Streamera (broji se u izvještaju kao `keptNewer`). Datumi bez zone ili nečitljivi tretiraju se kao UTC odnosno nepoznati.
- Popisi: vlasnik je korisnik koji ga vidi, a nije mu dijeljen (`Shares` iz `/Playlists/{id}`, Jellyfin 10.9+). Otvoreni popisi, i popisi na starijim verzijama gdje vlasnika nije moguće razlikovati, idu prvom povezanom korisniku kao javni. `import_playlists` pamti (server, popis, vlasnik) → ponovni uvoz zamjenjuje stavke umjesto da pravi kopije.
- River job `import.run` s napretkom po korisniku, probnim prolazom (čita u read-only transakciji, ništa ne piše) i izvještajem (uparivanje po načinu, uzorak od 50 neuparenih, popisi, preskočeni korisnici). Najviše jedan aktivni uvoz (parcijalni jedinstveni indeks).

**Posljedice:** nova migracija `00022_imports.sql` (`import_runs`, `import_playlists`). Ne uvoze se korisnički računi, kolekcije ni postavke. Uvoz nije provjeren protiv pravog Jellyfina, samo protiv lažnog servera u testovima prema javnoj dokumentaciji API-ja; prvo pokretanje treba biti probni prolaz.

## D-030 Ugrađene sigurnosne kopije: logički izvoz iz Go-a umjesto pg_dump (2026-11-10)
**Kontekst:** treba ugrađeni backup i restore (baza + `/config`, slike opcionalno, nikad mediji) koji radi iz admin UI-ja, kao zakazani zadatak i iz CLI-ja za pokvarene instalacije. Runtime slika (`debian:trixie-slim`) nema `pg_dump`; `postgresql-client` iz Debiana dodaje ~15–20 MB i mora odgovarati glavnoj verziji servera (pg17 u composeu), što se razilazi čim korisnik nadogradi Postgres. `pg_restore` uz to vraća i shemu, pa se ne bi uklopio s goose migracijama.
**Odluka:** server sam radi logički izvoz: sve tablice iz `public` (osim `goose_db_version` i River reda poslova) kopiraju se s `COPY … TO STDOUT` unutar jedne `REPEATABLE READ READ ONLY` transakcije (jedan snapshot), uz vrijednosti sekvenci i verziju sheme. Arhiva je jedan `.tar.gz`: `manifest.json` (verzija servera, shema, SHA-256 i broj redaka po tablici), `db/<tablica>.tsv`, `config/` (bez mape s kopijama), `avatars/` i, samo ako je uključeno, `images/`. Tablica koja se ne može pročitati (oštećeni zapisi) bilježi se u manifestu i preskače, ostatak kopije vrijedi. Kopije se pišu u `STREAMERO_BACKUP_DIR` (zadano `/config/backups`) kao `streamero-<UTC vrijeme>-<verzija>.tar.gz`, atomski (skrivena `.partial` datoteka pa rename). Zakazani zadatak „backup" (worker, provjera svakih sat vremena, kopija svaka 24 h) i „Napravi kopiju sada" idu kroz isti River posao; zadržava se zadnjih N zakazanih/ručnih kopija (učitane i one prije vraćanja brišu se samo ručno). Skeniranje biblioteke ne blokira kopiju, samo upozorava (u odgovoru API-ja, manifestu i logu). Postavke (uključeno, N, slike) spremaju se u postojeću tablicu `settings`, pa nova migracija nije potrebna (rezervirani broj 00023 ostaje neiskorišten).
Restore: arhiva se najprije cijela provjeri (checksumi, nazivi unosa); kopija s novijom shemom od binarija se odbija. Prije promjena piše se sigurnosna kopija trenutnog stanja. Ista shema: TRUNCATE + COPY u jednoj transakciji (strani ključevi se privremeno skidaju i vraćaju). Starija shema: shema `public` se ruši, migrira do verzije iz kopije, podaci se učitaju i zatim se migrira naprijed do trenutne verzije. Datoteke se raspakiraju samo ispod svojih korijena (`library.ResolveSafePath`); unosi izvan poznatih prefiksa ili s `..` odbijaju se. Iz UI-ja treba upisati točan naziv kopije; nakon vraćanja server i worker se ponovno pokreću (izlazni kod 75, signal workeru kroz Valkey). CLI: `streamero restore <datoteka>` traži upis `RESTORE` ili `--yes`. Sve rute su samo za administratore; nazivi idu kroz strogi uzorak i `ResolveSafePath`.
**Posljedice:** slika ostaje iste veličine i neovisna o glavnoj verziji Postgresa. Kopija nije prenosiva u druge alate (to nije `pg_dump` format), ali je tekstualni COPY format čitljiv i stabilan. Nove tablice automatski ulaze u kopiju; tablice izvan sheme `public` ili ekstenzijski podaci ne bi ušli (trenutno ih nema). Restore prekida aktivne sesije koje nisu u kopiji.

Kodek se kopira samo ako profil/razina/bit dubina videa poznato odgovaraju `CodecProfiles` klijenta, inače se transkodira; za to migracija 00024 sprema `video_profile`, `video_level`, `video_bit_depth` iz ffproba.
- Slike su javne kao u referentnom API-ju (playeri ih učitavaju bez zaglavlja); ID-evi su nasumični UUID-ovi, fotografije osoba su javne TMDb slike.
- 2FA računi se ne mogu prijaviti imenom i lozinkom (jasna poruka upućuje na Quick Connect); Quick Connect kod se odobri iz prijavljene web sesije (Postavke → Quick Connect) ili iz već prijavljenog klijenta. Initiate i AuthenticateWithQuickConnect su pod istim rate limitom kao prijava.
- Clean-room ostaje: samo javna API dokumentacija / OpenAPI opis i promatranje ponašanja klijentskih binarija; izvorni kod Jellyfina, Jellyfin-weba, Swiftfina, Emby-ja, Infusea, Kodi add-ona i SDK-ova se ne otvara.
**Posljedice:** compat sloj je javni ugovor i za medijske klijente; pokriven je unit testovima i integracijskim testom cijele klijentske sesije (`TestCompatClientSessionIntegration`). Bez WebSocketa (`/socket`) nema daljinskog upravljanja ni push obavijesti; DisplayPreferences se ne pamte; glazba je samo osnovna (direktno puštanje datoteke). Što je stvarno provjereno s kojim klijentom piše u INTEGRATIONS.md.

## D-032 Compat API i na korijenu adrese; CORS i `/socket` (2026-11-10)
**Kontekst:** vlasnik je ugasio Jellyfin; televizori su blokada. Službene TV aplikacije (Android TV, Samsung, LG) traže adresu servera, a dodavanje `/compat` korisnici ne očekuju (i neke aplikacije ga ne podnose dobro). Te aplikacije zovu Jellyfin putanje na korijenu (`/System/Info/Public`, `/Users/AuthenticateByName`, `/Items`, `/socket` …) u PascalCase obliku. Na korijenu već žive `/api/v1`, `/stream`, `/healthz`, `/readyz` i rute web klijenta (`/library/<id>`, `/settings/…`, `/item/<id>` …), pa jednostavno „sve što nije naše → compat" nije sigurno.
**Odluka:**
- Root router šalje zahtjev compat API-ju samo kad compat ruter ima **točno tu rutu** za tu metodu (`compat.Matches`, chi `Match` nad istom tablicom ruta, putanja bez obzira na velika/mala slova), ili kad prvi segment putanje počinje velikim slovom (klijentski stil; sve rute i datoteke web klijenta su malim slovima) — tada nepoznati endpoint dobije compat 404 i debug log, a ne HTML web klijenta. Sve ostalo ide web klijentu kao prije. `/api/v1`, `/stream`, `/compat`, `/healthz`, `/readyz` su montirani prije i uvijek imaju prednost.
- `/compat` ostaje. Postavka procesa `STREAMERO_COMPAT_ROOT` (zadano `true`); `false` vraća staro ponašanje. Namjerno env postavka, ne admin postavka u bazi: mijenja usmjeravanje cijelog servera, a rizik je mali.
- Nesudaranje se dokazuje testom koji parsira `web/src/app/router.tsx` i provjerava svaku rutu web klijenta (s parametrima) i statičke datoteke, plus popis klijentskih putanja (`TestCompatAtRoot*`). Nova ruta weba koja bi se sudarila ruši test.
- **CORS** na compat API-ju (bilo koji origin, bez `Allow-Credentials`): Samsung (Tizen) aplikacija je web aplikacija koja zove server s vlastitog origina. Zato compat zahtjevi **nikad** ne koriste web session cookie (`sessionFromCookie` ga ne pretvara u Bearer na compat putanjama); klijenti šalju token u zaglavlju ili `api_key`.
- **`/socket`** (WebSocket, `github.com/coder/websocket`): ista autentikacija kao ostali compat zahtjevi (token u `api_key` ili MediaBrowser zaglavljima; goli `Bearer` se odbija jer u njega pretvaramo cookie), po javnoj OpenAPI shemi poruka: na spajanje `ForceKeepAlive` (60 s), na `KeepAlive` odgovor `KeepAlive`, a naredbe s nadzorne ploče (`activity.Registry.Watch`) idu kao `GeneralCommand`/`DisplayMessage` i `Playstate`/`Stop`. Ništa drugo (daljinsko upravljanje, SyncPlay, događaji biblioteke) se ne šalje. Origin se ne provjerava (TV aplikacije imaju `file://`/app origin), jer vjerodajnica nikad nije ambijentalna.
**Posljedice:** klijenti koriste običnu adresu servera; rate limit prijave vrijedi i za korijenske putanje. Web klijent ne smije dobiti rutu koja počinje velikim slovom niti rutu koja je ista kao compat ruta (npr. `/items`, `/users`, `/web`) — test to hvata. Utičnice nadžive 60 s timeout middleware (vlastiti kontekst) i zatvaraju se kad klijent prestane slati keepalive (2× timeout).

## D-033 Otkrivanje servera na lokalnoj mreži (UDP 7359), zadano uključeno (2026-11-10)
**Kontekst:** TV aplikacije nude „servere na ovoj mreži": šalju broadcast „Who is JellyfinServer?" na UDP 7359 i očekuju JSON s adresom, id-om i imenom (javna dokumentacija o mrežnim portovima i javni model `ServerDiscoveryInfo`). Upisivanje IP adrese daljinskim upravljačem je najveća prepreka na TV-u. Pravilo protiv UDP broadcasta iz PLAN.md §6 odnosi se na iOS aplikaciju (Feather resign), ne na server.
**Odluka:** paket `server/internal/discovery`, pokreće ga `serve` nakon što je server spreman. **Zadano uključeno** (`STREAMERO_DISCOVERY=true`): to je LAN značajka bez ikakvih podataka osim imena i id-a servera koje i `/System/Info/Public` ionako daje, a bez nje TV korisnici moraju tipkati adresu. Zaštite: odgovara se samo na točan upit i samo pošiljateljima s privatnih, loopback ili link-local adresa; najviše jedan odgovor po izvoru u 250 ms i 20 u sekundi ukupno (odgovor je stotinjak bajtova, pa se ne može zloupotrijebiti za pojačavanje prometa ni ako je port dostupan izvana). Ako se port ne može zauzeti (npr. drugi server ga drži), samo se zapiše upozorenje. Najavljena adresa je `STREAMERO_DISCOVERY_URL`, inače `http://<adresa sučelja prema klijentu>:<HTTP port>`.
**Posljedice:** `deploy/docker-compose.yml` objavljuje `7359/udp`. Docker bridge mreža obično ne propušta LAN broadcast u kontejner, a kontejner zna samo svoju internu adresu: za otkrivanje treba `network_mode: host` ili barem `STREAMERO_DISCOVERY_URL`; inače se adresa upisuje ručno (INTEGRATIONS.md).

## D-035 Utiskivanje slikovnih titlova i prepoznavanje uvoda/odjavne špice kao zaseban zadatak (2026-11-11)
**Kontekst:** PGS, VobSub i DVB titlovi su slike: ne mogu postati WebVTT, a web player, iOS/Android i većina compat klijenata ih ne crtaju iz HLS-a. Uvod i odjavna špica tražili su se usput u analizi medija (usporedba s jednom susjednom epizodom, otisci se nisu čuvali, svaka nova epizoda ponovno je dekodirala cijelu sezonu), bez zamjene kad zvuk odjavne špice nije zajednički.
**Odluka (titlovi):**
- `PlaybackRequest.subtitleIndex` (indeks u titlovima datoteke, `-1` = bez) i `burnSubtitle` (utisni i tekstualni, npr. ASS sa stilom); `DeviceProfile.subtitleCodecs` = slikovni formati koje klijent sam crta iz datoteke u direct playu. Slikovni titl koji klijent ne može nacrtati → transkodiranje s titlom utisnutim u sliku, razlog „subtitle burn-in" (nadzorna ploča, `PlaybackInfo.reason`). Bez izbora (`subtitleIndex` izostavljen) utiskuje se samo **forced** slikovni titl koji bi preferencija titlova odabrala. Tekstualni titlovi i dalje idu kao WebVTT. Odgovor nosi `bitmapSubtitles` (ponuda) i `burnedSubtitle`.
- Slikovni: `overlay` (centrirano, poravnato dolje; platno PGS-a je veličine videa ili šire) nakon tonemapa, prije skaliranja. Vanjski `.sup` / `.idx`+`.sub` je drugi ulaz s `-itsoffset -start` umjesto `-ss` (traženje u `.sup` preskače titl koji je već na ekranu; `setpts` na grani titla zaglavi overlay). Tekstualni: libass `subtitles` filter (ASS stil i priložene fontove zadržava) preko simboličke veze u direktoriju sesije, tako da putanja medija nikad nije dio filter grafa; kod traženja su okviri pomaknuti na sat datoteke i natrag (`setpts`).
- **HW:** dekodiranje i filtri ostaju softverski, okviri se šalju GPU-u samo za enkoder (`hwupload` na kraju lanca), pa utiskivanje radi isto za NVENC/QSV/VA-API. `overlay_cuda/qsv/vaapi` imaju smisla tek uz hardversko dekodiranje, koje još ne postoji (FEATURES §6).
- Compat: `SubtitleStreamIndex` + `SubtitleProfiles` iz profila uređaja (`Embed` = klijent crta sam, samo `Encode` = utisni); utisnuti titl dobiva `DeliveryMethod: Encode`.
**Odluka (segmenti):**
- Zaseban River zadatak `media.segments` / `media.segments_all` (admin zadatak „Prepoznaj uvode i odjavne špice", 24 h, „Pokreni sada"); pokreće se i nakon svake analize medija. Analiza medija ostaje za poglavlja, segmente iz imena poglavlja i trickplay.
- Otisci: `fpcalc -raw` (Chromaprint, `libchromaprint-tools` u imageu) na zvuku koji ffmpeg dekodira od zadane pozicije (fpcalc ne zna tražiti); bez fpcalca ffmpegov `chromaprint` muxer daje iste vrijednosti. Prozori: prvih min(10 min, 30 %) i zadnjih min(5 min, 25 %) epizode.
- Inkrementalno: tablica `media_fingerprints` (migracija 00025) čuva otiske uz veličinu i mtime datoteke. Sezona se obrađuje samo ako ima novu ili promijenjenu epizodu; dekodiraju se samo te, ostale se uspoređuju iz baze (tako i starije epizode dobiju uvod kad stigne druga epizoda sezone).
- Usporedba: svaka epizoda s do 4 najbliže epizode iste sezone, uzima se odlomak s kojim se većina slaže (medijan početaka/krajeva) — jedna drukčija epizoda ne odlučuje za ostale. Odjavna špica koja završi do 10 s prije kraja produžuje se do kraja.
- Rezerva: kad zvuk ne nađe odjavnu špicu, `blackdetect` (≥90 % crnih piksela, mostovi do 3 s) na kraju epizode; uzima se zadnji tamni niz od ≥15 s koji seže do kraja. Rezultat se pamti u `media_fingerprints.black_credits_ms`.
- Prednost izvora: `manual > chapter > fingerprint > blackframe`; pisac nikad ne prepisuje jači izvor, detekcija briše samo svoje (`fingerprint`, `blackframe`) zapise, analiza samo `chapter`. Segmenti ostaju u `media_segments`, pa ih web, iOS, Android i compat (`/MediaSegments`) dobivaju bez promjena klijenata.
**Posljedice:** prvo pokretanje nakon nadogradnje ponovno izračuna otiske za sve epizode (stari nisu spremljeni). Utiskivanje uvijek znači softversko dekodiranje i transkodiranje videa. Web player nudi slikovne titlove s oznakom „utisnuto u sliku"; iOS i Android klijenti ih još ne nude (API je spreman). Preview/recap iz zvuka i detekcija teksta odjavne špice nisu napravljeni.

## D-036 Zajedničko gledanje (SyncPlay): WebSocket, stanje na serveru, korekcija drifta sa servera (2026-11-11)
**Kontekst:** grupa gledatelja treba isti queue, sinkroni play/pauzu/seek/brzinu, čekanje na onoga tko bufferira i ispravljanje razilaženja (drift). Klijenti: web, iOS, Android i (ako je izvedivo) compat TV aplikacije. Kanal mora biti dvosmjeran: klijenti šalju položaj otprilike svake sekunde i ping za mjerenje sata, server šalje stanje i korekcije.
**Odluka:**
- **Kanal: WebSocket** `GET /api/v1/syncplay/socket` (`github.com/coder/websocket`, već u projektu za compat `/socket`). SSE bi bio jednosmjeran: izvještaji o položaju (1/s po klijentu) i pingovi išli bi kao zasebni HTTP zahtjevi (više latencije i šuma u RTT mjerenju, više opterećenja), a mjerenje razlike satova traži isti kanal u oba smjera. iOS (`URLSessionWebSocketTask`) i Android (OkHttp) imaju WebSocket bez dodatnih ovisnosti i bez entitlementa. Ruta je izvan ogen routera (upgrade), ali poruke su opisane u `api/openapi.yaml` (`SyncClientMessage`, `SyncServerMessage`, `SyncGroup`); upravljanje grupama (popis, stvaranje, pridruživanje, izlazak, `GET /syncplay/me`) je običan REST iz spec-a.
- **Autentikacija i CSWSH:** isti token kao API (`Authorization: Bearer`, web koristi cookie koji router pretvara u bearer). Jer je cookie ambijentalan, socket provjerava `Origin` (mora odgovarati hostu); nativne aplikacije ne šalju `Origin`. Traži se dozvola `syncPlay` (admin uvijek); svaka stavka u queueu mora se moći otvoriti za svakog člana (isto pravilo kao `GET /items/{id}`): pridruživanje grupi čiji queue korisnik ne vidi i postavljanje queuea koji neki član ne vidi vraćaju `forbidden`, a popis grupa skriva takve grupe.
- **Model (paket `server/internal/syncplay`):** grupe su u memoriji. Član je **sesija** (prijava), ne konekcija: ponovno spajanje zadržava članstvo; član bez konekcije nikoga ne zadržava i ispada nakon 2 min. Stanja `idle` / `waiting` / `paused` / `playing`. Pozicija se prenosi kao `positionMs` + `anchorAt` (sat servera, Unix ms) + `speed`; dijeljena pozicija je `positionMs + max(0, now − anchorAt)·speed` dok grupa svira. Sinkroni start je `anchorAt` 600 ms u budućnosti, pa ga svi prime prije nego što se dogodi. Grupa kreće iz `waiting` kad nijedan spojeni član nije „nije spreman" i barem je jedan spreman; tko bufferira dulje od 20 s dobiva `lagging` i grupa ide dalje (sustigne ga korekcija). Izlazak člana nikome ništa ne zaustavlja. `next`/`previous` nose `entryId` na kojem je pošiljatelj, pa više članova na kraju filma preskoči samo jednom.
- **Sat:** klijent šalje `ping {clientTime}`, server `pong {clientTime, serverTime}`; offset = serverTime − (t0+t1)/2, uzima se uzorak s najmanjim RTT-om. Izvještaji `position {entryId, positionMs, at}` nose `at` na satu servera.
- **Drift se računa na serveru:** razlika ≤ 120 ms se ignorira; do 2,5 s server šalje `correction {mode: rate, rate, durationMs}` (±5 %, iznad 600 ms ±10 %, relativno na brzinu grupe; trajanje = |drift| / (brzina·postotak), klijent se nakon toga sam vraća na brzinu grupe); iznad 2,5 s `correction {mode: seek, positionMs}`. Dok korekcija traje, izvještaji tog člana se ne ocjenjuju. Pravila su na jednom mjestu (testirana), klijenti samo izvršavaju.
- **Rate limit po sesiji:** naredbe grupe (uključujući stvaranje i pridruživanje) 3/s uz burst 12, izvještaji 10/s uz burst 30; najviše 200 grupa na serveru. Odbijena naredba vraća `error {code: rate_limited}`.
- **Bez migracije** (sve je u memoriji); restart servera raspušta grupe — klijenti to vide kao `GET /syncplay/me` → 204.
- **Compat klijenti (TV aplikacije):** izvedivo, pa je napravljeno. Javni OpenAPI opis definira `/SyncPlay/{List,New,Join,Leave,Pause,Unpause,Stop,Seek,Buffering,Ready,Ping,SetNewQueue,SetPlaylistItem,NextItem,PreviousItem,Queue,…}`, `/GetUtcTime` i poruke `SyncPlayGroupUpdate` / `SyncPlayCommand` na `/socket`; to se mapira na iste grupe (`server/internal/compat/syncplay.go`). Compat socket se pretplati na grupu sesije i iz uzastopnih stanja izvodi poruke: `GroupJoined`/`GroupLeft`, `UserJoined`/`UserLeft`, `PlayQueue`, `StateUpdate` i naredbu (`Unpause` s `When` = `anchorAt`, `Pause`, `Seek` nakon seeka, `Stop`). Ti klijenti sami ispravljaju drift prema `When`/`PositionTicks`, pa im server ne šalje korekcije. Korisnicima s dozvolom `SyncPlayAccess` je sada `CreateAndJoinGroups`. Repeat/shuffle, premještanje i brisanje iz queuea i „ignore wait" se prihvaćaju bez učinka. Provjereno integracijskim testom sa simuliranim klijentom; stvarna TV aplikacija nije isprobana.
**Posljedice:** jedan proces drži grupe (Streamero ionako ima jedan `serve` proces). Chat nije u opsegu.

## D-037 Jedinstvena prijava (OpenID Connect) i LDAP ugrađeni u server (2026-11-11)
**Kontekst:** FEATURES §2 traži SSO (Authentik, Keycloak, Entra ID, Google) i LDAP bez plugina, na webu, u iOS/Android aplikacijama i za aplikacije trećih strana. iOS aplikacija se instalira preko Feathera (re-sign), pa ne smije ovisiti o entitlementima (PLAN.md §6).
**Odluka:**
- **Biblioteke:** `github.com/coreos/go-oidc/v3` (discovery, provjera ID tokena, JWKS s automatskim ponovnim dohvaćanjem pri rotaciji ključeva), `golang.org/x/oauth2` (code flow, PKCE), `github.com/go-ldap/ldap/v3` (LDAP v3, StartTLS, escape filtera). Sve tri su standard u Go ekosustavu i aktivno održavane; vlastita implementacija JWT/JWKS ili LDAP protokola bila bi rizičnija. U testovima još `go-jose/v4` (potpisivanje tokena lažnog providera; ionako ovisnost go-oidc-a).
- **OIDC tok:** authorization code + PKCE S256 + `state` + `nonce`. Server je jedini klijent kod providera (jedan redirect URI `{javna adresa}/api/v1/auth/oidc/{id}/callback`, točno podudaranje). Tok (`oidc_flows`) je jednokratan (DELETE … RETURNING, state se sprema samo kao hash, 10 min) i vezan uz preglednik kolačićem `streamero_oidc` (HttpOnly, SameSite=Lax, path `/api/v1/auth/oidc/`) — zaštita od login CSRF-a. ID token: potpis preko JWKS-a (samo asimetrični algoritmi koje provider najavljuje), `iss`, `aud`, `exp`, `nonce` (constant-time), `azp` ako postoji. Claimovi iz UserInfo se dodaju samo ako ih ID token nema i samo uz isti `sub`.
- **Javna adresa** je admin postavka (`auth.general.publicUrl`), ne izvedena iz `Host` zaglavlja: redirect URI mora biti stabilan i ne smije ovisiti o zaglavlju koje šalje klijent.
- **Web:** callback postavlja session cookie i šalje na `/`; nikakav token u URL-u.
- **Aplikacije:** custom URL shema `streamero://oidc` (iOS `CFBundleURLTypes`, Android intent filter). Ne associated domains / App Links (entitlement ne preživi Feather re-sign; svaki self-hosted server bi trebao `apple-app-site-association`/`assetlinks.json` za naš app ID). Ne loopback redirect (ASWebAuthenticationSession završava na shemi; HTTP server u aplikaciji je krhak). Shemu može prisvojiti druga aplikacija, zato server aplikaciji šalje samo **jednokratni kod** (`oidc_handoffs`, 2 min) koji se iskupljuje na `POST /auth/oidc/exchange` isključivo s PKCE verifierom koji je aplikacija sama generirala (challenge poslan na početku toka) — RFC 8252 obrazac; session token nikad nije u URL-u.
- **Povezivanje računa:** postojeća veza (provider + `sub`) → taj korisnik; eksplicitno povezivanje iz „Moj račun"; inače korisnik s istom e-poštom samo ako je `email_verified` (ili admin uključi „smatraj e-poštu potvrđenom" za provider kojim upravlja, npr. Entra) i samo ako je adresa jednoznačna; inače automatsko stvaranje (opcija) ili odbijanje. Admin grupa sinkronizira `is_admin` pri svakoj prijavi, ali nikad ne degradira zadnjeg admina. SSO ne traži Streamerov TOTP (MFA je posao providera).
- **LDAP:** postavke u `settings` (`auth.ldap`), lozinka servisnog računa se nikad ne vraća. Prijava ide kroz postojeći `Login` (web, aplikacije, compat API) pa vrijede IP rate limit i lockout. Korisničko ime se escapea (`ldap.EscapeFilter`), traži se točno jedan zapis, bind s praznom lozinkom se odbija (unauthenticated bind bi „uspio"), za nepoznate korisnike se troši isto vrijeme (argon2 dummy). Certifikat se provjerava po zadanom (StartTLS ili ldaps; opcionalni vlastiti CA). Grupe iz `memberOf` ili filtrom pretrage grupa (AD nested: matching rule 1.2.840.113556.1.4.1941). Lokalni računi bez LDAP veze i dalje koriste svoju lozinku; LDAP račun koristi imenik i za potvrdu lozinke (isključivanje 2FA, izlaz iz dječjeg profila).
- **Računi bez lozinke:** `password_hash = ''` (bez promjene sheme `users`); takav hash nikad ne prolazi provjeru, uz isti rad kao prava provjera.
- **Isključivanje prijave lozinkom:** dopušteno samo dok postoji omogućen admin s identitetom omogućenog providera ili LDAP-a; brisanje/gašenje zadnjeg takvog providera se tada odbija. Put oporavka: `STREAMERO_PASSWORD_LOGIN_RECOVERY=true` (env, ne postavka u bazi — mora raditi kad nitko ne može u UI) dopušta prijavu lozinkom **samo adminima**; opisano u `docs/SSO.md`.
- **Shema:** migracija 00027 (`oidc_providers`, `user_identities`, `oidc_flows`, `oidc_handoffs`, indeks na `lower(email)`). Client secret je u bazi kao i ostali API ključevi integracija (i u sigurnosnim kopijama, da restore ne pokvari prijavu); API ga nikad ne vraća.
**Posljedice:** prijava preko SSO-a mora krenuti s javne adrese (kolačić toka je na njoj). Entra „common" (multi-tenant) issuer nije podržan (issuer ne odgovara discovery dokumentu) — koristi se tenant ID. Aplikacije trećih strana (Infuse, TV) ne mogu SSO; za njih je Quick Connect. CI dobiva OpenLDAP service container (`osixia/openldap:1.5.0`) za LDAP integracijske testove.

## D-038 DLNA / UPnP AV media server za televizore bez aplikacije (2026-11-11)
**Kontekst:** vlasnikov LG televizor ne može pokrenuti ni Streamero ni Jellyfin-kompatibilnu aplikaciju (D-034), a svaki pametni TV ima ugrađeni DLNA player. Napisano samo prema javnim specifikacijama (UPnP Device Architecture 1.0, UPnP AV ContentDirectory:1 / ConnectionManager:1, DLNA smjernice kako su javno opisane) i javnim popisima formata proizvođača; izvorni kod drugih servera nije otvaran.
**Odluka:**
- Paket `server/internal/dlna`, bez UPnP biblioteke: SSDP, SOAP i DIDL-Lite su mali tekstualni protokoli, a vlastiti kod drži površinu napada malom i pod našim pravilima (samo LAN, limiti). Jedina nova ovisnost je `golang.org/x/net/ipv4` (BSD, Go tim; već je bila neizravna) za pridruživanje multicast grupi na svakom sučelju i odabir izlaznog sučelja.
- **Zasebni HTTP slušatelj** (`STREAMERO_DLNA_HTTP_ADDR`, zadano `:8788`), ne glavni router: glavni ima 60 s timeout zahtjeva, a pretvoreni stream traje satima; zasebni port se lako drži samo u LAN-u. SSDP na UDP 1900 sa `SO_REUSEADDR` (dijeli se s drugim UPnP softverom). Najavljuje se MediaServer:1 s ContentDirectory:1 i ConnectionManager:1; `ssdp:alive` pri uključenju i svakih 5 min, `ssdp:byebye` pri isključenju i gašenju.
- **Zadano isključeno** u postavkama (tablica `settings`, ključ `dlna` — nova migracija nije potrebna, rezervirani broj 00028 ostaje neiskorišten). Za razliku od otkrivanja (D-033), koje odaje samo ime i id, DLNA bez prijave daje cijelu biblioteku svakome u mreži, pa to mora biti svjesna odluka administratora. Uključivanje traži korisnika (i po želji profil) u čije ime DLNA radi; vrijede njegov pristup bibliotekama, roditeljsko ograničenje profila, jezik zvuka/titlova i pozicije. Slušatelji se pokreću sa serverom (`STREAMERO_DLNA=true`) ali bez uključene postavke šute (SSDP ne odgovara ni ne najavljuje, HTTP vraća 404); `STREAMERO_DLNA=false` uopće ne otvara portove.
- **Sigurnost:** odgovara se samo privatnim, loopback i link-local adresama (SSDP i HTTP). M-SEARCH: po izvoru 8 upita odjednom pa 2/s, ukupno najviše 40 upita/s (svaki do 5 odgovora od ~300 B), pa nema pojačavanja prometa. URL-ovi medija, titlova i slika potpisani su HMAC-om postojećim ključem i vrijede 8 h (`stream.URLTTL`); putanje uvijek kroz `library.ResolveSafePath`. GENA `SUBSCRIBE` šalje početni događaj samo natrag na adresu pretplatnika (bez zahtjeva prema trećim hostovima).
- **Stablo:** po biblioteci A–Z / Nedavno dodano / Žanrovi (filmovi; serije → sezone → epizode) ili Izvođači / Albumi / Nedavno dodano (glazba) te „Nastavi gledati" čije stavke kreću od spremljene pozicije. Browse s pagingom i sortiranjem (`dc:title`, `dc:date`), Search samo za `… contains "…"` (jeftino, kroz postojeću pretragu). Nazivi mapa na HR ili EN po postavci (TV ne vidi i18n web klijenta).
- **Profili po proizvođaču** (LG webOS, Samsung Tizen, Sony Bravia, generički) iz `User-Agent` / `X-AV-Client-Info` određuju što ide izravno (datoteka s byte-range, `DLNA.ORG_OP=01`) a što se pretvara: postojeći `stream.Decide` + novi `stream.ProgressiveArgs` (isti enkoderi, hardversko ubrzanje, tone mapping i limit istovremenih transkoda kao HLS) daju MPEG-TS H.264/AAC (ili MP3 za glazbu) na HTTP tijelo, s vremenskim premotavanjem (`TimeSeekRange.dlna.org`, `OP=10`, `CI=1`). Profilni naziv DLNA.ORG_PN navodi se samo gdje je nedvosmislen (MP3, JPEG_TN); kriva oznaka bi kod nekih TV-a blokirala reprodukciju, a bez nje rade. DLNA zaglavlja se šalju točno napisana (Go bi ih inače kanonizirao, npr. `Contentfeatures.dlna.org`).
- **Titlovi:** tekstualni kao SRT pored videa — Samsung kroz `CaptionInfo.sec` i `sec:CaptionInfoEx`, LG i Sony kao dodatni `text/srt` `res`; bitmap titlovi i titlovi uz stream koji kreće od pozicije se ne nude.
- **Napredak:** TV-i ne javljaju reprodukciju. Samsungov `X_SetBookmark` sprema se kao pozicija; inače se pozicija procjenjuje iz onog što TV dohvaća (bajtovi datoteke ili vrijeme pretvorenog streama) i sprema minutu nakon zadnjeg zahtjeva, uz postojeće pragove nastavka; nadzorna ploča prikazuje „trenutno se gleda".
- **Roditeljska ograničenja:** `library.RatingAge` pretvara oznake (MPAA, TV, UK, FSK, brojčane) u dob; skriva se naslov kojem on ili predak ima oznaku iznad granice profila; nepoznate oznake se ne skrivaju. Ostatak servera još ne primjenjuje `maxRating` — to je i dalje otvoreno.
**Posljedice:** compose objavljuje `8788` (HTTP); UDP 1900 je samo komentiran: bridge mreža ionako ne propušta multicast, a zauzet port na hostu (drugi DLNA server, UPnP pomoćnici) bi srušio `compose up`. Da ga TV-i sami pronađu, treba `network_mode: host` ili macvlan (INTEGRATIONS.md); `STREAMERO_DLNA_URL` postavlja najavljenu adresu. Provjereno neovisnim UPnP klijentom u Dockeru; pravi TV-i još nisu isprobani, pa su profili najbolja procjena iz javnih popisa formata.

## D-040 Preuzimanja za offline gledanje: poslovi na serveru, međuspremnik pretvorenih MP4-ica, sinkronizacija „najnovije pobjeđuje" (2026-11-11)
**Kontekst:** FEATURES §12 traži preuzimanje originalne datoteke (dozvola `download`), offline gledanje u iOS i Android aplikaciji u odabranoj kvaliteti (server pretvara), preuzimanje cijele sezone i „sljedećih N epizoda", sinkronizaciju napretka kad se uređaj vrati online i upravljanje prostorom. iOS se instalira preko Feathera (re-sign), pa ne smije ovisiti o entitlementima (PLAN.md §6).
**Odluka:**
- **Posao preuzimanja** (`downloads`, migracija 00030) je zahtjev jednog profila za jednu datoteku u jednoj kvaliteti: `original` (datoteka kakva jest) ili MP4 s H.264 + AAC stereo: `source` (izvorna rezolucija, konstantna kvaliteta iz postavki transkodiranja), `1080p` (najviše 1080 linija, ~5 Mbit/s) i `720p` (najviše 720 linija, ~2 Mbit/s). Zahtjev je idempotentan (vlasnik + datoteka + kvaliteta + audio zapis). `POST /downloads` prima film, epizodu, sezonu (sve epizode) ili seriju (`nextEpisodes` = sljedećih N neodgledanih nakon zadnje odgledane; `skipItemIds` = ono što uređaj već ima, broji se u N ali se ne preuzima ponovno). „Automatski" znači: aplikacija pamti pretplatu (serija, N, kvaliteta) i pri svakoj sinkronizaciji ponovi zahtjev; odgledane epizode te serije briše s uređaja.
- **Pretvorba** (`download_transcodes`) je zajednička svima koji traže istu datoteku u istoj kvaliteti i s istim audio zapisom (zadano po jezičnoj preferenciji profila). Radi je **worker** (River posao `downloads.transcode`, bez timeouta), u `/cache/downloads/<uuid>.mp4` (ime samo iz UUID-a). Video koji već odgovara (H.264 8-bit, bez HDR-a, ne previsok ni prebrz) se kopira, AAC stereo se kopira; inače `stream.DownloadPlan` + isti enkoderi, HW ubrzanje i tone mapping kao kod streama; `-movflags +faststart` (indeks na početku). Titlovi nisu u MP4: tekstualni titlovi idu kao **sidecar** `.srt`/`.vtt` (potpisani `/stream/sub/<file>/<i>.srt|vtt`), slikovni se ne nude. Artwork aplikacije spremaju s postojećih `/items/{id}/images/*` krajnjih točaka, a metapodaci (ItemSummary, opis, serija) dolaze u samom poslu.
- **Ograničenje istovremenih pretvorbi** je admin postavka (`settings` ključ `downloads`: `maxTranscodes` zadano 1, `cacheLimitGb` 50, `keepDays` 7), odvojena od limita streamova (`maxSessions`): preuzimanja nisu hitna i ne smiju pojesti mjesto gledateljima. Zauzimanje mjesta je pod Postgres advisory lockom (više gorutina workera); posao bez mjesta se odgodi (`JobSnooze` 15 s). Admin vidi pretvorbe (stanje, %, veličina, tko ih čeka, greška) na stranici Transkodiranje i može ih zaustaviti i ukloniti.
- **Restart:** pretvorba piše heartbeat svake 2 s. Pri pokretanju workera (jedini worker) sve „u tijeku" se vraćaju u red i ponovno stavljaju u River; periodični `downloads.maintain` (15 min) to radi za heartbeat stariji od 2 min. Gašenje workera vraća posao u red; greška ffmpega ga označi kao `failed` s porukom (novi zahtjev ga ponovno pokreće). Pretvorba datoteke koja je u međuvremenu zamijenjena (druga veličina) kreće ispočetka.
- **Čišćenje:** posao koji klijent nije obrisao briše se nakon `keepDays + 7` dana; pretvorba bez posla nakon 1 dana nekorištenja, svaka nakon `keepDays` dana bez preuzimanja; iznad `cacheLimitGb` brišu se najdulje nepreuzete gotove pretvorbe (i odmah nakon svake nove); zalutale datoteke u direktoriju starije od 1 h. Aplikacije brišu svoj posao čim je datoteka na uređaju, pa se međuspremnik prazni sam.
- **Posluživanje:** `GET /stream/dl/<posao>/<ime>` iza HMAC potpisa (opseg `/stream/dl/<posao>/`, 24 h; svježi URL daje `GET /downloads/{id}`), `http.ServeContent` (Range, If-Range — nastavak preuzimanja), `Content-Disposition: attachment`. Original uvijek ponovno kroz `library.ResolveSafePath`. Obrisan ili opozvan posao odmah daje 404, iako je potpis još valjan. Web „Preuzmi original" dobiva jednokratnu poveznicu `POST /items/{id}/original` → `/stream/orig/<file>/<ime>` (1 h), bez zapisa u `downloads`; preuzimanje se bilježi u audit log.
- **Dozvole:** svako preuzimanje traži `download` (to je dozvola za čuvanje kopija medija); pretvorene kvalitete još i `videoTranscoding` (troše isti resurs kao transkodirani stream). Vrijedi pristup bibliotekama (`allLibraries`) i **roditeljsko ograničenje** aktivnog profila: oznaka naslova ili bilo kojeg pretka (sezona, serija) iznad `maxRating` (preko `library.RatingAge`, kao DLNA) → `403 parental_limit`; nepoznate oznake se ne blokiraju.
- **Sinkronizacija** `POST /downloads/sync`: uređaj šalje sve stavke koje čuva i napredak zabilježen offline (`positionMs`, `played`, `updatedAt`). Server primjenjuje izvještaj samo ako je noviji od svog stanja (`user_item_data.last_played_at`) — **najnovije pobjeđuje**, s istim pragovima nastavka kao online; vrijeme iz budućnosti (pogrešan sat uređaja) računa se kao „sada", da ne zamrzne stanje. Odgovor sadrži stanje servera za sve stavke (aplikacija ga preuzima ako je novije od lokalnog) i `revoked`: stavke koje profil više ne smije čuvati (nema pristupa, oduzeta dozvola `download`, roditeljsko ograničenje, stavka obrisana); aplikacija te datoteke briše, a server briše njihove poslove. Da bi pravilo vrijedilo i za ručno označavanje, „označi kao odgledano/neodgledano" sada također postavlja `last_played_at`.
- **iOS:** pozadinska preuzimanja preko `URLSessionConfiguration.background` (ne treba entitlement, preživi Feather re-sign; nastavak nakon gašenja aplikacije kroz `handleEventsForBackgroundURLSession`), „samo Wi-Fi" kroz `allowsCellularAccess`. Offline biblioteka, artwork i metapodaci lokalno (Application Support), reprodukcija lokalne datoteke s nastavkom, lokalni VTT titlovi. Bez push obavijesti (APNs nije dopušten): status se osvježava dok je aplikacija aktivna.
- **Android:** WorkManager `CoroutineWorker` kao foreground posao (`dataSync`) s obaviješću o napretku; „samo Wi-Fi" kao `NetworkType.UNMETERED`; nastavak preuzimanja s Range; Media3 player s lokalnom datotekom i `.srt` sidecarom.
**Posljedice:** pretvorbe zauzimaju prostor u `/cache` (ograničeno postavkom). Veći broj istovremenih pretvorbi opterećuje CPU/GPU kao i streamovi. Napredak se uspoređuje po satu uređaja; jako pogrešan sat u prošlosti može izgubiti offline napredak (sat u budućnosti ne može pregaziti noviji online napredak duže od trenutka sinkronizacije). Opoziv djeluje tek pri sljedećoj sinkronizaciji uređaja (uređaj u zrakoplovnom načinu i dalje gleda ono što ima). Slikovni titlovi i višestruki audio zapisi u pretvorenim datotekama nisu u opsegu.

**Kontekst:** FEATURES §10 traži tunere (M3U, HDHomeRun), vodič (XMLTV), mapiranje kanala, gledanje s pauzom/premotavanjem i snimanje (pojedinačno, serije, padding, prioriteti, konflikti, post-processing, snimke kao biblioteka, retencija). - **Tuneri.** M3U s URL-a ili iz datoteke; datoteke samo kroz `library.ResolveSafePath` unutar medijskih mapa ili `/config/livetv`. Kodiranje: UTF-8 (± BOM), UTF-16 s BOM-om, inače Windows-1252. Adrese kanala samo mrežne sheme (http(s), udp, rtp, rtsp(s), rtmp(s)); ffmpeg dobiva `-protocol_whitelist`, pa playlist ne može natjerati server da čita lokalne datoteke ili koristi `concat:`/`subfile:`. HDHomeRun kroz `/discover.json`, `/lineup.json` i URL kanala; streamovi uvijek idu na adresu koju je admin upisao (iz lineupa se uzimaju samo port i putanja), DRM kanali se izostavljaju, kodeci iz lineupa (MPEG2/H264/HEVC, AC3/AAC/MPEG) pa nema probe. **Otkrivanje u LAN-u preko SSDP M-SEARCH-a** (HDHomeRun je UPnP media server) i potvrde preko `/discover.json`; vlasnički UDP protokol otkrivanja nema javnu specifikaciju koju smijemo koristiti, a cloud discovery bi slao podatke van — oboje odbačeno. Uz bridge mrežu otkrivanje ništa ne nađe, pa je ručna adresa ravnopravna. Dohvati (playliste, vodiči, API tunera, slike) idu kroz HTTP klijent koji nakon DNS-a odbija loopback, link-local (cloud metadata) i nespecificirane adrese; privatne LAN adrese su dopuštene jer tu žive tuneri.
- **Vodič.** XMLTV iz URL-a ili datoteke (i gzip), legacy kodiranja kroz XML deklaraciju (`htmlindex`), vremena s pomakom ili, bez pomaka, u vremenskoj zoni izvora (zadano UTC — DTD je tu nejasan). Osvježavanje je River posao u workeru: satni `livetv.guide_refresh_due` (također zadatak „Refresh guide") i `livetv.guide_refresh` za „Osvježi sada". Nepromijenjen izvor se preskače (ETag/Last-Modified → 304, isti SHA-256 sadržaja), a programi idu kroz privremenu tablicu: upisuju se samo novi i promijenjeni (hash po programu), uklanjaju se oni kojih više nema od prvog programa izvora nadalje. Id programa ostaje isti za isti (vodič, kanal, početak), pa zakazane snimke ostaju vezane. Jedno osvježavanje po vodiču odjednom (advisory lock). Slike programa i logotipi idu kroz `/stream/img/<url>/…` — potpisani URL u kojem je izvorna adresa, pa server dohvaća samo slike koje je vodič/playlista naveo; keš u `/cache/livetv-images`, SVG sa sandbox CSP-om.
- **Mapiranje:** automatski po `tvg-id`, pa po normaliziranom nazivu (bez naglasaka, velikih slova, interpunkcije i sufiksa HD/FHD/4K), pa za HDHomeRun po broju kanala; ručno mapiranje, „bez vodiča", skrivanje i kategorija po kanalu. Kategorije (filmovi, sport, vijesti, djeca) iz `group-title` i XMLTV `category` riječima na EN/HR.
- **Gledanje i time-shift.** Kanal je uvijek HLS (fMP4): postojeći `stream.Decide` na kodecima kanala (M3U se jednom probea ffprobeom i pamti), „direct" postaje remux, transkodiranje uz deinterlacing (`bwdif` samo za interlaced okvire) i iste dozvole kao film. **Time-shift je klizni HLS prozor** (`-hls_list_size` + `delete_segments`) duljine postavke „Time-shift buffer" (1–240 min, zadano 30): playeri (hls.js, AVPlayer, ExoPlayer) sami nude pauzu i premotavanje unutar prozora, a stari segmenti se brišu pa je veličina ograničena (tmpfs `/transcode`). Bez zasebnog DVR spremnika na serveru i bez novog playera. Gledatelji istog kanala s istom isporukom dijele jednu sesiju i jedan tuner. AAC iz MPEG-TS-a dobiva `aac_adtstoasc`. 503 izvora (HDHomeRun „805 All Tuners In Use" ili limit providera) postaje `tuners_busy`.
- **Tuneri se broje u `serve` procesu**, pa DVR petlja (raspored, snimanje, retencija) radi tamo, ne u workeru: jedini proces koji zna tko drži tuner. Snimka uzima tuner gledatelju ako nema slobodnog (snimke imaju prednost). Gledatelj i snimka istog kanala koriste dva tunera (namjerno jednostavno).
- **DVR.** Raspored svakih 5 s i na svaku promjenu: vremena zakazanih snimki prate vodič, serijska pravila dobivaju nova emitiranja, propuštene se označe kao neuspjele, konflikti se rješavaju **čistom funkcijom** `ResolveConflicts` (snimke koje traju prve, zatim prioritet, zatim ranije zakazana; prihvaća se ako vršno preklapanje na izvoru uz nju ne prelazi broj tunera; back-to-back nije preklapanje). Pravila serija: naslov se uspoređuje normalizirano; „samo nove" preskače emitiranja koja vodič označi kao ponovljena i svaku epizodu (S/E, `dd_progid` ili naslov epizode) snima jednom; kanal bilo koji ili određeni. Snimanje: `ffmpeg -c copy` u MPEG-TS na stdout, a Go dopisuje u datoteku — prekid izvora ili restart servera nastavlja u istu datoteku. Raspored datoteka prilagođen skeneru (`Naslov/Season N/… SxxEyy`, `Movies/Naslov (Godina)/…`, inače po datumu emitiranja), uz Kodi `.nfo` iz vodiča; biblioteka „Recordings" (mixed) stvara se s prvom snimkom, `STREAMERO_RECORDINGS_DIR` (zadano `/recordings`) dodaje se medijskim korijenima u `serve` i `worker`, a compose sada montira `/recordings` i workeru.
- **Post-processing** postavlja samo administrator (izvršava program na serveru): apsolutna putanja do izvršne datoteke, argumenti kao popis, svaki se nakon zamjene oznaka (`{path}`, `{title}`… popis u `docs/LIVETV.md`) predaje kao točno jedan argument — **bez shella**, pa naslov iz vodiča ne može ubaciti naredbu. Minimalno okruženje, radni direktorij mapa snimke, timeout; greška i zadnji izlaz spremaju se na snimku.
- **Retencija je opt-in** (zadano isključena): starije od X dana i/ili zadnjih N po pravilu serije. Briše se samo `.ts` na putanji koju je DVR sam spremio, nakon `ResolveSafePath` unutar mape snimki, i `.nfo` koji je napisao; „ukloni s popisa" u aplikacijama nikad ne briše datoteku.
- **Dozvole:** `liveTv` = gledanje, vodič, favoriti, popis snimki i pravila; `manageLiveTv` = tuneri, vodiči, mapiranje, postavke, zakazivanje snimki i pravila serija (zakazivanje troši tunere i disk, pa je to upravljanje). Ne iz dječjeg profila. Favoriti su po profilu/računu (kao napredak).
- **Compat API: izvedivo za gledanje.** Javni opis definira `/LiveTv/Channels`, `/LiveTv/Programs` (GET i POST), `/LiveTv/Programs/Recommended`, `/LiveTv/GuideInfo`, `/LiveTv/Info` i `TvChannel`/`Program` stavke; kanal se reproducira kroz postojeći `PlaybackInfo` kao `TranscodingUrl` (HLS, `IsInfiniteStream`), slike kanala preusmjeravaju na potpisani logo, `Policy.EnableLiveTvAccess/Management` prate dozvole. Snimke, timeri i serijski timeri vraćaju prazan popis (upravljanje u Streamero aplikacijama); `LiveStreams/Open` nije napravljen jer klijenti s `RequiresOpening: false` idu ravno na URL.
**Posljedice:** time-shift prozor zauzima RAM u `/transcode` (≈ bitrate × trajanje po aktivnom kanalu; 30 min HD remuxa je nekoliko stotina MB). Gledanje snimke koja još traje nije posebno podržano (datoteka se pojavi u biblioteci nakon kraja). Schedules Direct i detekcija reklama (comskip → segmenti) nisu u ovom koraku; comskip se može pokrenuti kao post-processing. Aplikacije (iOS, Android) nemaju mrežu vodiča, samo popis kanala s programom kanala.

## D-042 Titlovi transkodiranog streama koji kreće usred filma: pomak na serveru, klijent ga traži (2026-11-13)
**Kontekst:** transkodiranje s `-ss` bez `-copyts` daje HLS stream čije je vrijeme 0 = `startMs` u datoteci (nastavak, premotavanje izvan kodiranog dijela, promjena zvuka, sigurni stream), a WebVTT cue-ovi su apsolutni, pa su titlovi kasnili za `startMs`. Pogođeni: web i Android (ExoPlayer, sideload `SubtitleConfiguration`). iOS već radi ispravno: sam dohvaća VTT i uspoređuje cue-ove s apsolutnom pozicijom (`offset + currentTime`).
**Odluka:** ruta `/stream/sub/{fileId}/{n}.vtt` prima neobavezan, nepotpisan `offsetMs` (cijeli broj ≥ 0, ograničen trajanjem datoteke): svi cue-ovi pomiču se za toliko ranije, cue-ovi koji završe prije 0 se izbacuju, početak se reže na 0 (`stream.ShiftVTT`). Potpis i scope ostaju isti; SRT (offline sidecar), DLNA i compat ne koriste pomak. `playback.go` **ne dodaje** `offsetMs` sam u vraćene URL-ove: to bi već instalirane iOS buildove (Feather, sporo se ažuriraju) pomaknulo za `startMs` u krivom smjeru. Klijent ga dodaje kad je `method != "direct"` i `startMs > 0` (web od ovog PR-a; Android: jedna linija u `PlayerScreen.kt` pri izgradnji `SubtitleConfiguration`).
**Posljedice:** web i (nakon promjene) Android imaju točne titlove nakon restarta streama bez posla na klijentu oko cue-ova. Ako se jednom uvede `-copyts`, klijenti jednostavno prestanu slati `offsetMs`.
**Iznimka za naziv proizvoda u uputama (dopuna D-011/D-031):** tekst uputa za Seerr/Jellyseerr i *arr (`integrations.seerrIntro`, `integrations.arrIntro`) smije navesti „Jellyfin" / „Emby / Jellyfin" jer je to doslovan naziv opcije u tim aplikacijama koju korisnik mora odabrati. Naslovi, navigacija i ostali UI ne spominju drugi server (npr. „Uvoz s drugog medijskog servera").

## D-043 Skeniranje ne briše ono što ne može vidjeti (2026-11-13)
**Kontekst:** skener je sve datoteke koje nije našao brisao iz baze, a brisanje stavki kaskadno briše povijest gledanja, osobe, preuzimanja, segmente i članstvo u kolekcijama. Nečitljiva podmapa preskakala se tiho, a odmontirani disk često ostavlja praznu točku montiranja — oboje je izgledalo kao „sve je obrisano".
**Odluka:**
- Skener bilježi mape (i datoteke) koje nije mogao pročitati; ništa ispod njih se ne briše, kao ni sezone, serije, albumi i izvođači iznad onoga što ostaje.
- Ako bi se iz neke mape biblioteke uklonile sve poznate datoteke, ili više od polovice njih i barem 20, scan **ništa ne briše** (dodavanja i izmjene se i dalje upisuju). Broj zadržanih datoteka sprema se u `libraries.held_removals` (migracija **00032**), scan_error dobiva upozorenje, a web pokazuje poruku i gumb „Ukloni datoteke kojih nema" → `POST /libraries/{id}/scan?confirmRemoval=true`. Potvrda ne vrijedi za nečitljive mape.
- Nema posebnog stanja „offline" za stavke: zadržane stavke ostaju kakve jesu, a reprodukcija već javlja `file_missing` (v0.10.1).
**Posljedice:** namjerno brisanje velikog dijela biblioteke traži jedan klik potvrde. Prag (pola i barem 20) je konstanta u `scanner.go`.
